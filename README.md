# wish — простий Unix shell на C++

Проєкт з курсу «Операційні системи»: реалізація shell `wish` за специфікацією
[OSTEP processes-shell](https://github.com/remzi-arpacidusseau/ostep-projects/tree/master/processes-shell).

Shell читає команди або з клавіатури (інтерактивний режим із промптом `wish> `),
або з файлу (batch-режим), і запускає кожну програму в окремому процесі
через `fork()` + `execv()`, чекаючи на завершення через `waitpid()`.

## Можливості

- **Запуск програм** з пошуком у директоріях search path (спочатку лише `/bin`),
  перевірка через `access(..., X_OK)`.
- **Вбудовані команди**:
  - `exit` — вихід (з аргументами — помилка);
  - `cd <dir>` — рівно один аргумент, `chdir()`;
  - `path [dir ...]` — повністю замінює search path; порожній path — запускаються лише вбудовані команди.
- **Перенаправлення** `cmd args > file` — у файл ідуть і stdout, і stderr програми;
  файл перезаписується. Пробіли навколо `>` не обов'язкові.
- **Паралельні команди** `cmd1 & cmd2 args & cmd3` — усі запускаються одразу,
  потім shell чекає на кожну. Пробіли навколо `&` не обов'язкові.
- Будь-яка кількість пробілів і табуляцій між словами; порожні рядки ігноруються.
- Одне повідомлення про помилку для всіх випадків: `An error has occurred` у stderr.
  Після помилки shell працює далі; лише неправильні аргументи запуску
  (більше одного файлу або файл, який не відкривається) завершують його з кодом 1.

## Структура

```
tester/run-tests.sh        офіційний скрипт запуску тестів (ostep-projects)
processes-shell/
  wish.cpp                 вихідний код shell
  Makefile
  test-wish.sh             запуск офіційних тестів
  tests/                   офіційні тести (1..22)
```

Основні функції в `wish.cpp`:

| Функція            | Що робить                                                        |
|--------------------|------------------------------------------------------------------|
| `main`             | перевірка аргументів, цикл читання рядків через `getline()`      |
| `process_line`     | запускає всі команди рядка, потім `waitpid()` на кожну           |
| `split_parallel`   | ділить рядок по `&`                                              |
| `parse_command`    | розбирає `args [> file]` у `struct Command`, перевіряє синтаксис  |
| `tokenize`         | ділить текст на слова по пробілах і табуляціях                   |
| `run_builtin`      | виконує `exit`, `cd`, `path` у самому процесі shell              |
| `find_program`     | шукає програму в search path через `access()`                    |
| `start_program`    | `fork()`, у дитині — `open` + `dup2` для `>`, потім `execv()`    |
| `print_error`      | єдине повідомлення про помилку через `write()` у stderr          |

Обробка одного рядка: рядок → частини по `&` → у кожній частині `>` і
слова (`Command { args, out_file }`) → вбудована команда виконується в самому
shell, зовнішня — у дочірньому процесі → очікування всіх дочірніх процесів.

## Збірка і тести (Linux / WSL)

```sh
cd processes-shell
make
./test-wish.sh        # або: make test (продовжує після першого провалу)
```

Проходять усі 22 офіційні тести.

Примітка: тест 3 перед запуском перезаписує `tests/3.err` повідомленням
системного `ls`, тому після прогону тестів git може показувати цей файл як змінений.
